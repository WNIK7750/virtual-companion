# 按需记忆检索

When this guidance is supplied to the companion or explicitly read by a development agent, use it to choose and interpret the host's existing read actions. It defines no tools, permissions, or storage behavior.

Start with the admitted context already supplied for this turn. If it is enough to answer, answer without extra lookup. Otherwise identify the smallest missing relation, entity, or time span and choose an exposed action that could fill that gap:

- `recall(query)` uses the host's configured semantic or lexical lookup. Returned `memories` contain complete source text that the host has already rechecked and admitted with record/version identity. Check that text against the question; do not repeat `read_memory` merely because it arrived through recall. A relevance match is not proof of the claim or a complete inventory.
- `browse_memory(node_id, cursor?)` opens one directory level. Labels and previews are navigation only. Follow `next_cursor` when another page could fill the gap, and use `read_memory` for a selected record whose full text is not already admitted. `catalog_coverage=complete` concerns the host-reported qualified-record scope; it does not mean all source bodies were read or all historical material is available.
- `read_memory(references=[{record_id, version}])` retrieves and admits complete source text for selected directory references. Use the returned original, not its preview, to establish the relation. Reuse already admitted record/version pairs rather than spending a call to read them again.

When the current host exposes public-web actions, use `search_public(query)` for a missing public fact or current lookup, and `extract_public(url)` when an exact public page is already known and its captured text is needed. Keep the query or URL public and minimal; do not send private chat or use web matches to fill a user or character history. These actions share the host's current public-call allowance; choose an available action without assuming that search can be followed by extraction in the same turn. Use the returned `public_evidence` with its actual status, URL, captured text and range. A snippet, truncated excerpt, empty result or failed fetch cannot establish a complete page, global absence or unsupported conclusion. If the action is absent or spent, use admitted evidence and preserve the remaining gap.

Use only the parameters in the current host schema. The recall query itself is plain text. When the host explicitly exposes `constrained-recall.v1`, optional `exact_terms` require all specified literal phrases or identifiers to match; optional `conditions` match positive sourced fact keys (`subject`, `predicate`, `scope`). Unknown fact keys cannot satisfy a condition. Without that contract, preserve the relevant name, phrase, or identifier in the plain query and check the returned original. Similar wording or numbering can refer to a different entity; literal matching alone is not entity disambiguation. Do not infer time-range, numeric aggregate, SQL, or other unexposed capabilities.

For `deep-memory.v1` and `dialogue-memory.v1`, the three read actions share at most six calls per turn; a read admits at most eight originals and the union holds at most 24. For dialogue fragments, every full user or assistant member counts as an original, including a repeated anchor. Preserve each member's role and origin: a past assistant expression is not proof of a user fact or a completed operation. A frozen visible subset does not establish a complete reply, and an unknown occurrence time stays unknown. These are ceilings. The 64 KB bound belongs to the overall context, with other context and navigation consuming capacity. Follow the current `evidence_access.limits`, `calls`, `stop_reason`, and exposed actions; do not calculate a separate 64 KB allowance for originals. Source processing and repair do not reset spent read calls. When the host stops reads or omits the action, answer from the admitted evidence or state the remaining gap; do not bypass the stop with another action.

For a multi-hop answer, preserve each supported link and its record/version. Check subject, polarity, modality, time, frequency, quantity, and whether the statement is current or revised. A matching source is still not proof of a stronger interpretation. Do not merge conflicting versions into one certainty or fill missing user details with plausible guesses. A miss, partial directory, or selected Top-K cannot establish a global absence, total, or extremum; describe only the inspected scope when coverage is insufficient.

The existing `memory` source-processing action is separate and may write or revise records. Do not use it as a read fallback or treat a request or promise to save as proof that saving completed. Keep lookup mechanics out of an ordinary user-facing reply; give the useful answer and state material uncertainty naturally.
